# Day 04 · 设计题：网络爬虫

## 背景

搜索引擎、网页存档（Internet Archive）、大模型训练语料、价格监控，背后都是爬虫。写一个单机爬虫只要几十行：从队列取 URL → 下载 → 解析出新链接 → 放回队列。难的是把它放大到每月几十亿个页面：

- **去重**：几百亿个 URL 「见没见过」放哪里？（今天的动手题）
- **礼貌**：不能对同一个网站几千个并发把人家打挂，要遵守 `robots.txt`。（Day 3 的限流）
- **优先级**：首页和新闻页比十年前的论坛帖子更值得先爬、更值得常爬。
- **分布式**：几百台机器怎么分工？一个网站该由谁负责？（Day 2 的一致性哈希）
- **健壮**：爬虫陷阱、超大页面、DNS 慢、机器宕机后从哪里继续。

## 题目

为一个搜索引擎设计 **通用网络爬虫**，只爬 HTML 页面。

**功能需求**

- 给定一批种子 URL，持续发现并下载新页面。
- 下载的 HTML 原样存储，供下游的索引系统使用（索引不在本题范围内）。
- 遵守每个站点的 `robots.txt`；对同一个域名，同一时刻最多 1 个连接，两次请求之间至少间隔 1 秒（或 `robots.txt` 的 `Crawl-delay`）。
- 已经爬过的页面要定期 **重爬**：经常变化的页面（新闻首页）每天重爬，几乎不变的页面每月一次。
- 内容完全相同的页面（镜像站、同一页面的不同 URL）只存一份。

**非功能需求**

- 可扩展：加机器就能线性提高吞吐。
- 健壮：单台机器宕机不丢已发现的 URL，重启后能继续；能识别并跳出爬虫陷阱。
- 礼貌：任何时候都不能违反上面的单域名约束，**即使爬虫有几百台机器**。

**规模（已知条件）**

- 每月下载 **10 亿个页面**（新页面 + 重爬）。
- 平均每个页面 **500 KB**（HTML 原文），压缩后约 100 KB。
- 每个页面平均包含 **50 个链接**。
- 已知的不同 URL 总数约 **100 亿**，平均 URL 长度 100 字节。
- 原始页面保存 **5 年**。
- 平均一次 HTTP 下载耗时 1 秒（包含 DNS、建连、传输）。

## 要回答的问题

全部写在 `DESIGN.md` 里，下面这些问题一定要覆盖到：

1. **估算**（第 2 节）：
   - 平均和峰值的下载 QPS？出口带宽？
   - 5 年的页面存储（压缩前后）？
   - 每秒要做多少次「URL 见过没有」的检查？
   - 100 亿个 URL 去重，用 `set` 存原文 vs 存 8 字节指纹 vs 布隆过滤器（1% 误判），分别要多少内存？
   - 下载耗时 1 秒，要达到目标 QPS 需要多少并发连接？大概要多少台机器？
2. **高层架构**（第 5 节）：画出一个 URL 从「被发现」到「页面落盘」经过的所有组件（种子 → URL Frontier → 下载器 → DNS → 解析 → 内容去重 → URL 过滤 / 去重 → 回到 Frontier），说明每个组件的职责。
3. **URL Frontier**（第 6 节，最重要）：既要 **优先级**，又要 **礼貌**，用一个 FIFO 队列做不到。请设计 Frontier 的内部结构：
   - 优先级怎么定（PageRank、更新频率、站点权重……）？
   - 怎么保证同一个域名同时只有一个连接、间隔至少 1 秒？（提示：Mercator 的「前端按优先级分多个队列，后端按域名分多个队列 + 一个按『下次可访问时间』排序的堆」）
   - 100 亿个 URL 的 Frontier 放不进内存，怎么放到磁盘上，又不让磁盘 IO 成为瓶颈？
4. **去重**（第 6 节）：
   - **URL 去重**：先做什么规范化（大小写、末尾斜杠、`#fragment`、`utm_*` 参数、参数排序）？然后用什么判断见过没有？布隆过滤器误判 1% 意味着什么？可以接受吗？
   - **内容去重**：完全相同用什么（哈希摘要）？「几乎相同」（只差一个广告、时间戳）用什么（SimHash / MinHash）？只需要讲清楚思路。
5. **分布式与分区**（第 7 节）：几百台爬虫机器之间怎么分工？按 URL 哈希还是按 **域名** 哈希？为什么按域名分区能顺便解决礼貌问题？加机器、机器宕机时域名怎么重新分配（Day 2）？跨机器发现的链接怎么转交？
6. **健壮性**（第 7 节）：
   - 爬虫陷阱：无限日历页面、`/a/b/a/b/a/b/...`、带会话 ID 的 URL，怎么识别和防御？
   - DNS 为什么会成为瓶颈？怎么解决？
   - 下载器进程宕机，正在爬的 URL 和内存里的 Frontier 怎么不丢（检查点、WAL，明天 Day 5 会实现）？
7. **重爬与新鲜度**（第 6 或 7 节）：怎么估计一个页面的更新频率？`ETag` / `Last-Modified` / `If-Modified-Since` 能省掉什么？
8. **取舍**（第 8 节）：至少写 3 行，比如布隆过滤器 vs 精确去重、按域名分区 vs 按 URL 分区、BFS vs 按优先级。

## 要求

- 限时 45 分钟，前 5 分钟只做需求澄清和估算，不要一上来就画架构。
- 每个技术选型都要写「为什么」，以及「放弃了什么」。

## 面试追问（做完后自己先想想）

- 如果只爬一个超大网站（比如整个维基百科），按域名分区就失效了：所有 URL 落在同一台机器上，而且礼貌约束让你一秒只能爬一个页面。怎么办？
- 要爬 JavaScript 渲染的单页应用（SPA），架构上要加什么？成本会变成多少倍？
- 怎么让爬虫优先发现「刚刚发布的新页面」？（`sitemap.xml`、RSS、外链出现的速度）
- 布隆过滤器用了一年，已经远超设计容量，误判率涨到 20%，但你不能停机。怎么在线换一个更大的？
