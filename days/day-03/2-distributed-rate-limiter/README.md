# Day 03 · 设计题：分布式限流服务

## 背景

动手题里的限流器只在一台机器的内存里工作。可真实的 API 网关有几十上百台机器，同一个用户的请求会被负载均衡打到不同的机器上。每台机器各限各的，用户的实际额度就变成了「单机额度 × 机器数」；把单机额度除以机器数呢，负载又不可能绝对均匀，还会误伤正常用户。

所以需要一个 **所有网关共享状态** 的限流服务。这道题考的是：状态放哪里、怎么做到原子、限流服务本身慢了或挂了怎么办，以及在每秒百万次检查的规模下，精确和性能之间怎么取舍。

## 题目

为一家公开 API 平台（类似 Stripe / GitHub API）设计一个分布式限流服务，给所有 API 网关调用。

**功能需求**

- 支持按 **多种维度** 限流：API Key、用户 ID、IP，以及「某个 API Key 调用某个接口」这种组合维度。
- 规则可以配置，例如：
  - 免费用户每个 API Key 每分钟 100 次，付费用户每分钟 1000 次；
  - `POST /v1/charges` 每个 API Key 每秒 25 次；
  - 同一个 IP 登录失败每 15 分钟最多 5 次。
- 一个请求可能同时命中多条规则，**全部通过才放行**。
- 被限流的请求返回 HTTP 429，带上 `Retry-After` 和 `X-RateLimit-Limit`、`X-RateLimit-Remaining`、`X-RateLimit-Reset` 响应头。
- 规则修改后 **1 分钟内** 在所有网关上生效，不用重启。

**非功能需求**

- 限流检查给每个 API 请求增加的延迟：P99 < 5 ms。
- 限流服务本身 **不能成为单点**：它挂了的时候，API 不能跟着全挂。
- 精度：允许少量超发（比如额度的 1% 到 5%），但不能出现「额度 × 机器数」这种量级的超发。自己定一个可接受的误差，并说明理由。
- 支持多机房部署（先考虑 2 个机房）。

**规模（已知条件）**

- 网关集群 200 台机器。
- 峰值 API 请求 **100 万 QPS**，平均每个请求命中 3 条规则。
- 活跃的限流 key（API Key、用户、IP 加起来）约 **5000 万** 个。

## 要回答的问题

全部写在 `DESIGN.md` 里，下面这些问题一定要覆盖到：

1. **估算**（第 2 节）：限流存储每秒要承受多少次读写？每个 key 的状态多大（令牌桶和滑动窗口日志分别算）？5000 万个 key 总共要多少内存？一台 Redis 扛得住吗？要几台？
2. **部署位置**（第 5 节）：限流逻辑放在哪里？对比下面三种，给出选择：
   - 嵌在每台网关进程里（库）
   - 独立的限流服务（网关通过 RPC 调用）
   - 网关直接读写共享的 Redis
3. **算法选择**（第 6 节）：结合动手题，选哪种算法？为什么？不同规则能不能用不同算法？
4. **原子性**（第 6 节，最重要）：两台网关同时对同一个 key 做「读取计数 → 判断 → 写回」，会发生什么？至少对比两种解法：
   - Redis `INCR` + `EXPIRE`（固定窗口）能解决吗？两条命令之间进程挂了会怎样？
   - Lua 脚本实现令牌桶 / 滑动窗口，在 Redis 里原子执行。脚本里的「当前时间」从哪里来？用网关的时间还是 Redis 的 `TIME`？为什么？
   - （可选）分布式锁为什么在这里不合适？
5. **数据模型**（第 4 节）：Redis 里的 key 怎么命名？value 存什么？过期时间设多少？规则本身存在哪里，怎么下发到网关？
6. **扩展与热点**（第 7 节）：
   - 限流 key 怎么分片到多台 Redis（回想 Day 2 的一致性哈希）？
   - 某个大客户一个 API Key 每秒 5 万次请求，全落在同一个 Redis 分片上，怎么办？（提示：本地预取一批令牌、本地计数 + 定期同步）
   - 多机房：每个机房各有一套 Redis，全局额度怎么分？跨机房同步会带来多少误差？
7. **故障处理**（第 7 节）：Redis 超时或者挂了，网关是 **放行（fail-open）** 还是 **拒绝（fail-closed）**？不同规则（普通 API 限流 vs 登录防暴力破解）的选择一样吗？Redis 主从切换时，计数丢失会造成什么后果？
8. **取舍**（第 8 节）：至少写 3 行，比如精确 vs 延迟、集中式 vs 本地、fail-open vs fail-closed。

## 要求

- 限时 45 分钟，前 5 分钟只做需求澄清和估算，不要一上来就画架构。
- 每个技术选型都要写「为什么」，以及「放弃了什么」。
- 第 6 节的原子性，请写出 Lua 脚本的 **伪代码**（10 行左右即可，不用能跑），说明每一步读写了什么。
- 写不出来的地方先空着，标一个 `TODO`，review 的时候我们重点讨论。

## 面试追问（做完后自己先想想）

- 网关每个请求都要跟 Redis 往返一次，3 条规则就是 3 次。能合并成 1 次吗？
- 限流和熔断、降级有什么区别？上游是被限流的 429，还是自己扛不住的 503，客户端应该怎么区别对待？
- 客户端收到 429 后立刻重试，会不会加重问题？`Retry-After` 和客户端的指数退避加抖动怎么配合？
- 如果要求「每个用户每月 100 万次调用」这种长周期额度（计费相关，不能丢），还用 Redis 吗？和秒级限流的设计有什么不同？
