# Day 16 · 动手题：Merkle 树（校验、证明、快速找差异）

## 背景

两台机器上各有一份 100 GB 的数据，理论上应该完全一样。怎么确认它们真的一样？如果不一样，怎么找出 **哪里** 不一样？

- 把 100 GB 全部发给对方比较：太慢、太贵。
- 各自算一个整体哈希，只比哈希：能知道「不一样」，但不知道是哪一块不一样，只能全部重传。

**Merkle 树**（哈希树）同时解决这两个问题：

```
              root = H(H12 + H34)
             /                    \
     H12 = H(H1 + H2)       H34 = H(H3 + H4)
       /        \              /        \
  H1=H(块1)  H2=H(块2)    H3=H(块3)  H4=H(块4)
```

- 把数据切成块，每块算一个哈希作为叶子，两两合并往上算，最后得到一个根哈希。
- **对比**：先比根。根一样，所有数据都一样，结束。根不一样，就比左右两个孩子，只往不一样的那一边走下去。如果 100 万个块里只有 1 块不同，只需要比较约 `2 × log₂(100 万) ≈ 40` 次哈希，就能定位到它。
- **证明**：想向别人证明「第 3 块的内容是 X」，不需要给出所有数据，只要给出从第 3 块走到根的路上每一层的 **兄弟哈希**（约 log n 个）。对方自己算一遍，看能不能算出同一个根。

它无处不在：

- **Dynamo / Cassandra 的反熵**（Day 5、Day 9 里提到的）：两个副本各自对自己的 key 范围建 Merkle 树，比对后只同步不一样的 key。
- **Git**：每个提交就是一棵 Merkle 树的根。
- **BitTorrent / IPFS**：下载的每一块都能用根哈希验证有没有被篡改。
- **云盘同步**（今天的设计题）：快速找出文件的哪些块变了。
- 区块链、证书透明度日志（RFC 6962）。

### 0. 哈希规则（必须按这个来，测试会核对哈希值）

- 叶子：`leaf_hash(data) = sha256(b"\x00" + data)`
- 内部节点：`node_hash(left, right) = sha256(b"\x01" + left + right)`
- 返回的都是 32 字节的 `bytes`（`.digest()`，不是十六进制字符串）。

为什么要给叶子和内部节点加不同的前缀？想一想：如果不加，攻击者能不能把「两个叶子哈希拼起来」伪装成一个叶子的数据？（这叫第二原像攻击，RFC 6962 就是这么防的）

### 1. `MerkleTree(blocks)`

- `blocks` 是一个 `bytes` 列表（数据块）。空列表抛 `ValueError`，有不是 `bytes` 的元素抛 `TypeError`。
- **建树**：第 0 层是所有叶子哈希。每一层从左到右两两合并成上一层；如果这一层是 **奇数个**，最后一个节点 **原样提升** 到上一层（不和自己合并）。一直合并到只剩一个节点，就是根。
- `root`：根哈希。`len(tree)`：叶子个数。`height`：层数减 1（只有 1 个叶子时为 0）。
- `node(level, index)`：第 `level` 层（叶子是第 0 层）第 `index` 个节点的哈希。
- `proof(index) -> list[(sibling_hash, sibling_is_left)]`：从叶子往上，每一层的兄弟节点哈希，以及兄弟在左边还是右边。某一层没有兄弟（被原样提升的那个节点），这一层 **跳过**。`index` 越界抛 `IndexError`。
- `MerkleTree.verify(root, block, proof) -> bool`（静态方法）：从 `leaf_hash(block)` 开始，按证明逐层往上算，最后和 `root` 比较。
- `update(index, block)`：把第 `index` 块换成新数据，**只重新计算从这个叶子到根的路径**（`O(log n)`），不要整棵树重建。测试会检查结果和重建一棵新树完全一样，并且用一个 10 万块的树计时。

### 2. `diff(a, b) -> DiffResult(indices, nodes_compared)`

- 两棵树的叶子个数不同抛 `ValueError`。
- 从根开始 **递归** 比较：两边这个位置的哈希相同，就不再往下走；不同就分别比较它的孩子（只有一个孩子的节点，就只比较那一个）；到了叶子层还不同，就把这个叶子的下标记下来。
- 返回不同的叶子下标（升序）以及一共比较了多少次节点（每比较一对节点算 1 次，包括根）。
- 例：8 个叶子、只有 1 个不同时，比较次数是 `1 + 2 + 2 + 2 = 7`。
- **不能** 一上来就逐个比较所有叶子。

### 3. 反熵：比较两个 KV 存储

Dynamo 风格的副本之间用 Merkle 树对比 key。key 太多，不可能每个 key 一个叶子，所以先把 key 分到固定数量的 **桶** 里，每个桶是一个叶子：

- `bucket_of(key, depth) -> int`：`sha256(key 的 UTF-8)` 的前 4 字节按大端解释成整数，取 **最高 `depth` 位**。一共 `2^depth` 个桶。
- `bucket_block(items) -> bytes`：把一个桶里的 `(key, value)`（都是 `str`）按 key 排序后编码成一个数据块：每一项依次写入 `4 字节大端的 key 长度 + key + 4 字节大端的 value 长度 + value`（长度按 UTF-8 字节数），整个序列再取 `sha256(...).digest()`。空桶就是 `sha256(b"").digest()`。为什么要先排序？为什么要写长度，不能直接拼接？
- `build_store_tree(store, depth) -> MerkleTree`：`store` 是 `dict[str, str]`，`2^depth` 个桶各算一个数据块，建树。`depth` 不在 `1..20` 之间抛 `ValueError`。
- `anti_entropy(store_a, store_b, depth=8) -> list[str]`：用两棵树的 `diff` 找出不同的桶，**只在这些桶里** 逐个比较 key，返回值不同（或者只在一边存在）的 key，排好序。

## 接口

```python
t = MerkleTree([b"block1", b"block2", b"block3"])
t.root.hex()                 # 64 位十六进制
p = t.proof(2)
MerkleTree.verify(t.root, b"block3", p)    # True

t2 = MerkleTree([b"block1", b"CHANGED", b"block3"])
diff(t, t2)                  # DiffResult(indices=[1], nodes_compared=...)

anti_entropy({"a": "1", "b": "2"}, {"a": "1", "b": "3", "c": "4"})   # ["b", "c"]
```

函数签名见 `solution.py`，不要改。

## 进阶（可选）

- `diff` 要求两棵树叶子个数相同。云盘里文件中间插入了一个字节，所有块都往后错了一位，按固定大小切块的话几乎所有块都变了。**内容定义分块**（content-defined chunking，用滚动哈希决定在哪里切）是怎么解决这个问题的？（rsync、Dropbox、restic 都用它）
- 现实中两台机器不在同一个进程里。把 `diff` 改成一问一答的协议：A 发出一层的哈希，B 回答哪些不一样，A 再发下一层。一共要几轮往返？怎么减少轮数（一次发多层）？
- 反熵的桶数怎么选？桶太少，一个桶里 key 太多，比较慢；桶太多，树太大。Cassandra 默认的 Merkle 树深度是 15，为什么？
